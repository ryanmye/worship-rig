The two failures on every config are orchestrator-owned tests, not T08:

- `unit.clock` (`tests/test_clock.cpp:66`): first sound 576 frames late at 96 kHz, 192 at 32 kHz = 6 ms, T03's
  master look-ahead. The test expectation needs + 6 ms·rate.
- `unit.golden-analytic` (`tests/test_golden.cpp:116-117`): expects `click-120-44` to render silent with skips
  "until T07"; T07 has landed. The case should be retired or pointed at a fixture that is still unsupported.

Claims checked one by one:

- Garbage ring + stash, never on the event ring (V13): `Graph::push` routes Garbage to its own SPSC ring, parks in a
  1024 stash, retries in order each quantum; `unit.runtime` "58k owned payloads" and "stash flushes in order" pass.
  Bound arithmetic is plausible (every pointer comes from a command; drained every 1024 sends and every loop turn).
- Ended bits + synthesized `VoiceEnded{sub:1, b:-1}` per lost slot on `Dropped`: code matches, test passes.
- Slot levels = 0.5·(L+R) of the post-pan strip over 256 frames: matches the JS AnalyserNode tap (Chromium down-mixes
  stereo to mono as 0.5·(L+R)); see open item 1 for retiring strips.
- RTA: Blackman a0 0.42 / a1 0.5 / a2 0.08 with x = i/N, |X|/N, Nyquist dropped, smoothing 0.8 with non-finite -> 0,
  bytes clamp(round(-dB·2)) = engine-api.json `messages.rta`. Consistent with Chromium RealtimeAnalyser, but only
  checked analytically (open item 4).
- Recorder 16-bit = recorder-processor.js (clamp, NaN -> 0, asymmetric scale, Math.round): code and test agree.
- G6 8 Hz floor, G7 `hostLatency`, G9 `state` -> `load{start}` -> reply, `busy`, watchdog, `restarted:true`, every
  error code of engine-api.json has a scenario (`unit.bridge-conformance`): tests read and pass.
- Audio thread (rig_render -> FIFO -> Graph -> meter/rec sinks, clock-map seqlock write): no allocation, no locks, all
  loops bounded by the quantum; rec/meter rings are SPSC with acquire/release. One futex wake per control turn when
  events are pending (semaphore release; not a lock).

## Fixes made (owned files)

1. **`std::binary_semaphore` released past its max (UB)** `src/api/engine.{h,cpp}`: `post`, `onControl`,
   `postHostEvent` and the destructor called `wake_.release()` unconditionally from any thread, so the counter could
   reach 2+ (precondition violation; libc++ hardened builds assert it, which is the Apple target). All releases now
   go through `Engine::wakeControl()` (release only on the `wakePending_` false -> true flip), and the control loop
   clears `wakePending_` only after it actually acquired (a timeout no longer re-arms a second release).
2. **Restart lost its pending state on audio_stop's completion** `src/api/engine.cpp` `hostAudioState`: every state
   report cleared `pending_`, and the header defines `RIG_DEVICE_SUSPENDED` as audio_stop's completion, which both
   devhost (`audio_host.cpp:313`) and Apple (`RigAudio.swift:51`) send before the reopen. So during a restart the
   watchdog was disarmed and a second restart was not `busy`. SUSPENDED now keeps the start pending. New test
   `unit.runtime` "restart: audio_stop's SUSPENDED completion keeps the new start pending" (fails without the fix:
   `busy` count 0).
3. **`RIG_DEVICE_RUNNING` via `rig_host_audio_state` left rendering off**: only non-running states touched
   `started_`, so after an interruption the engine emitted `state running` but rendered silence. `started_ = s ==
   RUNNING` now. New test "an interruption stops rendering; RIG_DEVICE_RUNNING from the host resumes it".
4. **rig_destroy could start the device again**: the device thread ran every queued job after `hostStop_`, i.e. an
   `audio_start` after the platform's `audio_stop`, rendering into an engine being destroyed. Queued jobs are now
   dropped on stop (a job already running still completes).
5. **RTA torn-copy check off by one quantum** `src/meter/meter.cpp`: the writer stores a quantum before it advances
   `written`, so the safe lap is `kRing - N - kQ`, not `kRing - N`.
6. **Recorder level peak** `src/rec/rec.cpp`: peaks are of the clamped sample (recorder-processor.js), so `level`
   never exceeds 1; NaN still ignored.
7. `src/runtime/README.md` documents 2-4.

## Open items

1. **Low: slot meters omit retiring strips.** JS `slotLevel` keeps the outgoing strip connected to the slot's
   analyser until it is disposed, so held/pedalled voices on a retiring channel show on that slot's meter after a
   song switch; the graph meters only `stripSlot(i)`. Change (orchestrator, `graph.cpp`): record the origin slot of
   each retiring channel (the Model knows it at retire time; e.g. `aux` on the AttachUnit that moves the strip) and
   sum the retiring strip's 0.5·(L+R) sample-wise into that slot's accumulator before peak/rms.
2. **Low: id-less errors are not deduplicated.** Contract 6.1 says fire-and-forget errors surface as a `warn`
   "deduplicated"; `bridge.cpp fail()` emits one `warn` per failure. Change: keep the last (code, op, message) and
   suppress identical warns within one control turn / 1 s.
3. **Low: rig_destroy blocks forever if `audio_start` hangs.** The device thread is joined; a host blocked inside
   AUHAL hangs destroy. Either document "audio_start must return" in `rig_engine.h` (with T08's proposed device-thread
   note) or give the device thread a bounded join and leak it with a detached shared state.
4. **Low: no Chromium vector for the RTA.** Only an analytic bin-centred sine test. Add
   `tools/golden/vectors/dump-analyser.mjs` (AnalyserNode fftSize 2048, smoothing 0.8, getFloatFrequencyData over
   several quanta of a chirp) and compare dB within 1e-3.
5. **Orchestrator:** fix `tests/test_clock.cpp:66` (+ 6 ms look-ahead) and retire/retarget
   `tests/test_golden.cpp:108-118`; apply T08's proposed `rig_engine.h` comment (audio_start/audio_stop run on the
   core's device thread, in order).

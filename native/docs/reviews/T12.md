## Fixed in owned files

1. **Medium, contract 2.3: `slots.<i>.release` was snapshotted at note-on** (`sampler.cpp noteOn`:
   `v.releaseOverride = relOverride_`), so a `ReleaseOverride` op arriving while the key is down did not apply to that
   note. JS `_release` sets `voice.releaseOverride` just before `noteOff`; T11's synth reads it at release too. Now read
   in `releaseAt` (`if (relOverride_ > 0) v.releaseOverride = relOverride_`), voice field reset to 0 at note-on. New test
   `ReleaseOverride is read at release` (measured with the fix: held −16.1 dB, after −inf; on the old code it should
   fail by computation, not run: the own release τ 0.12 s leaves the tail only ~7–22 dB down at 0.1–0.3 s).
2. **Medium (latent until T13 builds at prepare): `SamplerService::build` cancelled every in-flight load of its
   channel.** A build for a prepare that is superseded or not yet committed starved the sampler still playing on that
   channel of its late samples forever (realtime only; offline decodes inline). Removed: a late table that reaches a
   newer unit is already rejected by instSeq and comes back as Garbage; `onCommit` still cancels loads of channels
   that no longer hold a sampler.
3. **Medium on Apple (libc++), latent on Linux: `~SamplerService` released the references of in-flight loads into
   the cache.** `Model::services_` is a `std::vector`; libc++ destroys elements back to front, so the "cache"
   service (registered after `inst_sampler`, `rig_modules.inc`) is already destroyed when `~SamplerService` runs →
   use-after-free whenever an engine is destroyed with decodes pending (realtime). libstdc++ (this box) destroys front
   to back, so Linux never shows it; found by reading, not reproduced (no libc++ build here). Now the destructor
   detaches the leases first and touches nothing in the cache (the references die with the cache). The orchestrator may
   also want `~Model` to destroy services in an explicit (reverse-registration) order for every module.
4. Nit: `deferGarbage` overflow comment said "keep it"; it leaks the previous entry (by design: no free on the audio
   thread). Comment corrected.

## Code review notes (no action)

- Audio thread: no locks (`gEnvMu` only in the factory / service ctor-dtor, control thread), no allocation (voices
  placement-new into T11's pool; zone tables travel as `Owned` and die on the control thread; `unit.sampler` alloc test
  under `rt::RenderScope` passes), loops bounded by the pool (160) and the layer/sample counts. Denormals: biquad state
  relies on `rt::RenderScope` FTZ/DAZ in `Graph::render` (as Chromium's DenormalDisabler).
- Ports checked against `sampler.js` / `instruments.js`: layer pick, nearest sample (tie → lower), playbackRate
  `2^((n−s)/12)`, detune = bend·100 with τ 8 ms ramp, velocity LPF `2000·6^v` with Q `20·log10(√½)` rounded to float
  like the AudioParam, velocityDb spans 10/24 dB, `setNow` env, release τ = r/6.9 and stop at 1.3·r, fade-out min 3 ms,
  allOff 30 ms, steal 20 ms with BasicAllocator's policy (`AnyReleased`), tone `500·40^clamp(t+0.3m)` with Nyquist
  bypass and 15 / 30 ms ramps, trim after tone. Explicit 2-channel env up-mix of mono buffers matches.
- Voice size ≈ 20.4 KB (BufferSource 13 528 B + Gain 6 704 B + 2 biquads); pool of 160 slots = 3.3 MB address space
  per sampler unit, touched only as used. Cost (g++ Release, this box): 64 voices 155 µs per 128-frame block
  single-layer (5.8 % of a 48 kHz block), 71 µs multi-layer.
- Not covered by any golden (unit-tested only): bend, morph, tone param, release override, steal, undamped notes,
  late zone tables.

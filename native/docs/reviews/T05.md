### Attributing the chorus residual (checked independently)

I dumped the LFO×depth signals from Chromium with an OfflineAudioContext and fed them to `fx::DelayNodeKernel`. Both
chorus goldens then come out **bit-exact** on both channels. `wa::Oscillator` (T11a) differs from Chromium from
sample 0, by at most 2.4e-7 on the raw LFO. The delay kernel is therefore exact, and the whole residual comes from
T11a.

The residual is bounded by ulp(read position), about 2.4e-4 frames at a buffer length of 2333, times the slope of the
input. With a noise input that bound is the size of the exact tolerance.

## Fixes made in this review (owned files, uncommitted at the time of writing; the earlier skeptic's two are in
checkpoints 9f256c1 / 35313ca)

1. `fx/delay.cpp` `addTimer` (earlier skeptic): a newer `SwitchRetry` reuses the pending retry's slot. Before this
   fix, a burst of time changes while the other line was busy filled the 16-slot table and evicted live ring/flush
   timers. Test: "a burst of time changes while the other line is busy".
2. `fx/lofi*` (earlier skeptic): `Lofi.hold` is now hold-only (`LofiState::holdOnly`). JS `hold()` calls only
   `_engage`; re-issuing the ramps restarted their setTarget curves. Test: "hold-only apply (Lofi.hold)".
3. `fx/chorus.cpp` and `fx/lofi.cpp`: NaN in delayTime now falls back to `DelayNode.delayTime.defaultValue`, which
   Chromium reports as 0. The code had used the 7 ms / 5 ms option values. This was measured in Chromium 157
   (`defaultValue` 0, `maxValue` float(0.05)). Nothing reachable produces NaN today; this is about faithfulness.
4. `fx/delay.cpp`: corrected the comment that said a full timer table "cannot happen". It can, under a long run of
   time changes above 5 %: stale ring-end timers live for up to 8 s. Evicting the oldest is safe, because a line's
   live timer is always its newest.

## Code read: real-time safety and kernel fidelity

- `DelayNodeKernel` against `delay.cc` and `delay_sse2.cc`: the buffer length (128 + TimeToSampleFrame kRoundUp), the
  copy-before-read, the float read position `cvtepi32(w) + (len − desired)`, both wraps, the truncation and the
  interpolation all match. Delay times are always a-rate in 157 (`DelayHandler::Process`, `IsAudioRate()` branch). I
  checked that `-ffp-contract=off` is set.
- `sumAndClip` matches `CalculateFinalValues`: connections summed in order, then NaN replaced by the default, then
  Vclip.
- Audio-thread paths (`process`, `apply`, timers, switch, panic, lofi engage): no heap use and no locks.
  - `wa::Param` has a fixed event capacity.
  - `wa::BufferSource` re-assignment is a value copy.
  - `WaveShaper::setCurve` only hands over a pointer.
  - The lofi curve cache mutex is taken only on the control side (`LofiState::make`).
  - `runTimers` terminates: each pass removes a timer, and a retry callback re-adds only a future timer.
  - Denormals are flushed by `rt::RenderScope` (core).
- JS parity of the control logic (fx.js:1132-1335 and 1339-1563, audio.js setParam/_applyFx/setTempo) holds line by
  line, except for the deviations the builder lists.

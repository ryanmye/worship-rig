## Fix made (T13-owned files)

**F1 (medium, T13 regression): a device rate change between prepare and commit left the incoming song on the old
rate.** Since T13 builds instruments and strips at prepare, a plan's units are not attached yet when `RateChanged`
arrives: the InstrumentService re-points only Inst0..15, `SongGraph::onRateChanged` only the retiring synths, and
nobody touches the plan. The committed synth.js instrument kept its old-rate wavetables. Reproduced: a `synth:bell`
prepared at 48 kHz, rate changed to 96 kHz, then committed and played A4 sounded at **880 Hz**. Before T13 units were
built at commit, so this could not happen.
- `src/model/song.cpp` `SongGraph::onRateChanged`: when a plan is pending and the rate changed, its Fresh slots are
  deleted (never attached: control thread) and rebuilt with `build(patch, i, sampleRate)`.
- `src/model/graph_build.cpp` / `song.h`: `build()` takes an optional explicit sample rate (the time base may still
  hold the old rate when the event is handled).
- `tests/test_song.cpp`: new case "rate change between prepare and commit (T13 review)": now 440 Hz (was 880).
- The rebuilt instrument takes a new `instSeq` (a new instrument, contract 7.15); JS never changes rate in a context,
  so no golden is affected. All 112 renders are byte-identical before and after the fix.

## Open items (not fixed here)

**O1 (low; `src/model/patch.cpp`, orchestrator-frozen, the T13 INTERFACE-CHANGE region): explicit JSON `null` takes
the role default, JS takes the PARAMS default.** `normalizePatch` does `{...base, ...s}`, so `"highNote": null`
overrides the role value and `clamp()` then maps null to the PARAMS default (127 / sends 0 / mono 'off' /
bendEnabled false). `applyRoleDefaults` treats null as absent, so a Bass slot with `"highNote": null` gets 59 natively
and 127 in JS (same for sends, mono, bendEnabled). The store never writes null today, so no song is affected yet.
Exact change, in `applyRoleDefaults`:
```
-      return !v || yyjson_is_null(v);
+      return !v;  // JS: {...base, ...s} keeps an explicit null, clamp(null) = the PARAMS default
```
and fix the comment above it: the PARAMS defaults of those rows are 0 / 127 / 'off' / false, not NaN (checked in
`params_gen.inc`). With the change, null falls through to what `applyTable` / `numField` already do for null (skip
the value, keep the row default), which is the JS result. Worth a 4-line unit test in `test_model.cpp`.

**O2 (low; T13 + T11): an instrument param is stored only when its coalesced flush runs.** `Model::set` coalesces
`setInstrumentParam`, which writes `cfg.params` inside the handler, so for up to 10 ms `get state` / a prepare's
`paramsMatch` read the old value, and a commit inside that window drops it (JS stores at call time, then coalesces
only the instrument call). Harmless for sound today (a mismatch only builds a fresh instrument), but it is a
contract difference. Change: store first, coalesce only the send: split T11's `setInstrumentParam` into a store step
(run in `Model::set` before the push) and the op send (the coalesced closure).

**O3 (low; T13): reused-channel params outside the catalogue are not re-sent.** JS `_applySlotCfg` also sends
`cfg.params` keys that have no meta when they differ from the previous song's; native loops over catalogue metas
only. Affects instruments without a catalogue entry (user samplers). Add the second loop in `applyReused` (JSON keys
of `cfg.paramsJson` not in `e->params`, compared against `prev.paramsJson`).

**O4 (info; T14): the command gate delays a note-off that resolves to a retiring channel.** For a commit whose `when`
lies ahead of the clock, a note-off of an old-song note posted between the commit call and `when` is routed to
`RetireInst<j>` and gated to the move frame, so the release starts at the commit frame instead of the note-off time.
Not reachable today: the UI commits with `when` = now (controller `call('commit', token, {})`) and
`fixture_runner` posts events sorted by time, so every event before a commit is posted before it. T14 should keep
note targets resolving to the unit that holds the note *at the note-off frame* if it ever posts out of order.

**O5 (info; orchestrator, ARCHITECTURE 7.1 / T00c memory budget): prefault resident cost.** Measured per the
builder: +1.9 MB per synth.js instrument (16 x 119 888 B), +0.33 MB per sampler. Worst case 16 synth slots + 32
retiring = about 91 MB resident on the iPad profile. Write it into 7.1 next to the 128-voice pool numbers.

**O6 (info; T16): `setLowResource` no longer fans out `onMemoryPressure` to every service.** Only reverb (level 1,
on) and the cache (`setLowResource`) are told. Today no other service implements the hook, so nothing changed, but
the drone freeze (`drone.setFrozen(v)` in JS) has no notification path. T16 needs a hook (for example
`Service::onSongState` carrying a low-resource flag, or `DroneService` reading `Model::lowResource()`): orchestrator
decides, since `services.h` is frozen.

**O7 (info; T14): `auto-filter-cutoff` now passes** (4.3e-6, statistical) through T13's 10 ms coalescing of
`slots.<i>.params.*`. T14 should list it as passing rather than re-derive it.

Frozen-file changes reviewed and acceptable as written (orchestrator to log in INTERFACE_LOG): `model.h` (SongGraph
pimpl + friend, `songGraph()`, `setDynamicRange()` / `dynamicRange()`, `plans_` removed, `sg_` declared last so it is
destroyed first), `patch.cpp` role defaults (values match `ROLE_DEFAULTS` / `defaultSlot`; only O1 differs). The
manifest diff only adds the four twins plus the header counters (`lastRun`, `tiers`, `generatedAt`).
`voice_alloc.h` prefault: the pool is constructed on the control thread only (instruments are built at prepare),
`freeSlot()` returns the lowest free index, so playing stays inside the touched slots.

## Real-time review

Nothing T13 adds runs on the audio thread except `InstShell::process` (one forward + one relaxed-cost atomic
store) and the forwarding virtuals (`apply`, `param`, `setSampleRate`, `liveVoices`, `asInstrument`, all forwarded;
`giveBack` is a non-virtual helper, so nothing is swallowed). Prepare / commit / retire / poll / gate / coalescing run
on the control side; units are `new`ed at prepare and deleted on the control side (never-attached plan units in
`discard`, attached ones through Garbage). Same-frame Move-then-Attach ordering at a commit relies on the graph heap's
`seq` tie-break (checked: `later()` compares `seq`). No DSP, smoothing or Chromium kernels in T13's files; fader
moves port `fx.js trackedMove` / `linFrom` / `rampTo` call for call (including linFrom's double cancel-and-hold).

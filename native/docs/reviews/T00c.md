## Fixed (owned files)

1. **Pin budget bypassed by back-to-back `preload {pin:'add'}`** (medium). `withinPinBudget(add=true)` counted what
   was already pinned with `pinnedBytes()`, which only sees DECODED pins; preloads are answered before their decodes
   land, so every `pin:'add'` call got a fresh 85 % budget. Now the existing pins are counted by
   `estimateBytes(pins)` (stored size once decoded, estimate before). `samples/cache_service.cpp`; test added in
   `unit.t00c` ("pin budget": a second add after a full first one keeps nothing; an already pinned key is kept, not
   counted twice). Header comment corrected (it is not a prefix: a key that does not fit is skipped, later smaller
   keys may still fit).
2. **Reverb byte cap exceeded during every crossfade on the iPad profile** (medium, T04 finding 1 only half closed).
   The test sampled `bytes()` only after the fade settled (27.7 MB); sampled every 0.1 s the same switch sequence hit
   **35.07 MB > 32 MB**: the new slot's state was counted at the swap but nothing evicted until the fading slot went
   Idle. `ReverbPool::swapUnit` now calls `evict()` at the swap (Idle slots LRU, then idle kernels). Measured after:
   worst **30.19 MB** settled and during crossfades (14.1 MB kernels, <= 16.1 MB slot state). The test now checks the
   crossfade worst too. Reverb goldens unchanged (desktop cap never binds); `unit.reverb`, `unit.reverb-worker` pass.
   ARCHITECTURE 7.1 row updated.
3. **`Engine::fifoResidue` under-reported the FIFO latency for block sizes that share a small gcd with 128** (low).
   `(128 - b mod 128) mod 128` is only the residue after the first block; the residue cycles through multiples of
   gcd(b, 128), worst `128 - gcd(b, 128)`. Simulated with the `fifoRead` logic over 1e5 callbacks: 441 -> 127 (was
   71), 470 -> 126 (was 42), 96 -> 96 (was 32); 64/192 -> 64 and multiples of 128 -> 0 unchanged. Fixed in
   `api/engine.h` (Euclid gcd, no allocation), the comment in `engine.cpp`, the test, ENGINE_CONTRACT (latency
   reporting) and ARCHITECTURE 7.1. Only matters when the OS grants a non-power-of-two size (iPad may round).
4. **`audio {bufferFrames}` was stored before the `busy` check** (low): a restart rejected with `busy` still changed
   the request for the next open. Moved below it (`api/engine.cpp`).
5. `params.cpp` change now carries the literal `INTERFACE-CHANGE(T00c)` marker (it said "T00c D3").

## Open items

- **O1 (nit, orchestrator)**: `include/rig/rig_engine.h` (API 1.1 members, `RIG_HOST_SIZE_V1`, `RIG_METERS_SIZE_V1`)
  and `api/registry.h` say "added by T00c" / "(T00c D3)" but carry no literal `INTERFACE-CHANGE(T00c)` marker as the
  rules ask. Not touched here: editing `rig_engine.h` forces a full rebuild in every agent's build dir. Add the marker
  with the next real change to that header.
- **O2 (low, T13)**: `rig_meters.slot_count` is set only by the bridge's `opCommit` (`Graph::setSlotCount`); a commit
  that does not go through the bridge (fixture runner, tests calling `Model::commit`, any internal commit T13 adds)
  leaves it stale. Exact change: set it where the commit happens, e.g. `Model::commit` sends it (a `Graph` setter
  reachable through the Model's sink, or `Engine` hooks `onCommit`), and drop the call from `bridge.cpp`.
- **O3 (low, T13 note)**: the graph only keeps `NoteOn` off retiring channels for `kAllSlots`; a targeted `NoteOn` to a
  `RetireInst` slot is applied. BUILD_PLAN calls it a graph rule. Either add
  `if (c.op == Op::NoteOn && isRetireInstSlot(UnitSlot(c.target))) return;` in `Graph::apply`'s targeted branch, or
  reword BUILD_PLAN to "the Model never sends one".
- **O4 (test infra)**: `rt.realtime` now carries the T00c FIFO tests and a 16-slot soak, so under ASan and `ctest
  -j2` the pre-existing `xruns <= 3` check (`test_realtime.cpp:101`) fails (14 xruns; passes alone). Change: give the
  ASan branch the TSan treatment (MESSAGE instead of CHECK under `__SANITIZE_ADDRESS__`), or set `RUN_SERIAL` on
  `rt.realtime` in CMakeLists.txt. The builder's "one timing-sensitive re-run" is consistent with this, but both
  logged full ASan runs show the failure.
- **O5 (T11/T12 note)**: the reference allocator in `TestInstrument` (D1 policy order) steals with a hard restart and
  raises no `VoiceEnded` for the stolen voice; the contract asks the instruments for a 20 ms steal fade. It is the
  reference for the ORDER only.
- **O6 (low)**: `withinPinBudget` estimates each key alone, so a legacy key served by a long stand-in already counted
  in the same request is counted twice (conservative: pins fewer, never more).
- **O7 (open question, unchanged)**: no global voice ceiling (DECISIONS D1): 16 slots x 64 test voices already take
  2430 us of the 2667 us quantum on this box; real voices cost more. Needs Ryan's word.
- Apple sources (`rig_apple_audio.c`, `RigAudio.swift`, `RigHost.swift`) are unbuilt here; read only: the request path
  is consistent (64 passed through, granted size read back), compile on the Mac.

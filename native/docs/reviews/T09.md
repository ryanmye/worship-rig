## Claims checked

- **4/4 on four C++ configurations; JS 103/105 with 2 skipped; run-all unit green.** Reproduced. The counts here
  include the review's additions.
- **End-to-end `RIG_DEVHOST=1` 2/2.** Flaky before this review: 2 failures in 18 runs, each time with `ctx.state`
  stuck at `'suspended'` while the device was running. A loop of 40 bare start() calls reproduced it once. The bug is
  in `bridge-engine.js` (fix 1). After the fix: 60/60 loop runs and 108/108 JS.
- **"no core files touched", INTERFACE-CHANGE none.** True. This review touched none either.
- **"dropped" means no page is connected.** True: `Server::send` counts while `hasPage_` is false, and `drainQueue`
  counts when no active page exists.
- **Playwright 1.56 pins Chromium 1194; only 1243 is installed.** True (`playwright-core/browsers.json`
  revision 1194; `/opt/pw-browsers/chromium-1243`).
- **recorder.js diff (2 lines).** Legal JS. A derived constructor may return an object before `super()`, and nothing
  in `app/js` uses `instanceof Recorder`. It still needs Ryan's approval (orchestrator).
- **RT path (`AudioHost::renderInterleaved`).**
  - No locks and no allocation: the planar buffers are sized in `start()` before `ma_device_init`.
  - It runs under `RenderScope` (allocation-trap marker plus FTZ/DAZ).
  - The loop is bounded by `frames / maxBlockFrames`.
  - The only atomics are relaxed counters.
  - `steady_clock` reads are vDSO and do not block.
  - Restart closes the old device (`ma_device_uninit` joins its callback) before the buffers are resized.

  No smoothing and no DSP kernels live in T09, so there are no Chromium ports to check.

## Fixes made (owned files)

1. **`app/js/engine-bridge/bridge-engine.js`: an `audio` reply's state snapshot overwrote a newer `state` event**
   (medium). `start()`, `restart()` and `setSinkId()` ran `_applyState(reply)` after `await`. When the reply and the
   following `{ev:'state', state:'running'}` arrive in the same batch, or in the same socket read under Node's
   WebSocket, the event is dispatched first. The continuation then wrote the older snapshot (`'suspended'`) back, and
   `ctx.state` stayed `'suspended'` with the device running. The fix adds `_stSeq`, counting state events, and a helper
   `_audioReq` that applies the reply snapshot only when no state event arrived after the request went out. This is
   safe because the core emits a `state` event for every change. Test: `test/unit/engine-bridge/state-order.test.mjs`
   (3 cases); 2 of them fail on the old code.
2. **`native/devhost/src/{http.h,http.cpp,server.cpp}`: no Origin check on the WebSocket upgrade** (medium, security).
   Browsers let any site open `ws://127.0.0.1:8440/__rig/ws`. Because the newest page wins, any web page Ryan visited
   while the dev host ran could take over the engine, kick the real UI off (close 4000), and start or stop `rec` takes
   in his recordings folder. A new `webSocketOriginAllowed(origin, host)` lets through:
   - no `Origin` (Node and the tests);
   - http(s) loopback origins (127.0.0.1, localhost, [::1]) on any port, so `server.js` plus `?devhost=` still works;
   - the request's own `Host` when it is an IP literal (`--bind 0.0.0.0` on a LAN).

   It refuses everything else with 403, including DNS names (so DNS rebinding fails too) and `null`. `httpHead` now
   knows 403. Tests: a new `devhost-http` case (14 checks) and a `devhost-relay` check that a foreign-Origin page gets
   403 and does not replace the active page. Real Chromium (boot-devhost, ui-core subset) and Node's WebSocket still
   connect.
3. **`native/devhost/src/audio_host.cpp`: wrong `host_time_ns` for later pieces of a long callback** (low).
   A callback longer than `maxBlockFrames` is rendered in pieces. Piece k used `now() + latency` read after rendering
   piece k−1, which is about 50 µs later instead of `k·4096/rate` later. It now uses
   `t0 + latency + done·1e9/rate`. That is the first-frame host time that `rig_render` expects (rig_engine.h).
4. **`native/devhost/tests/test_relay.cpp`: the relay take was silence.** See "Silence" above. `tests/util.h`
   `WsClient::open` gained an `extraHeaders` argument for the Origin test.
5. **`native/devhost/README.md`**: documents the Origin rule.

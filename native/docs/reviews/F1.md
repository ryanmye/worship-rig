## Findings

**Event semantics (verified).**
- **Shape.** `{"v":1,"ev":"load","phase":"samples","loaded":{id:bool}}` matches ENGINE_CONTRACT 6.5 and
  `mock-native.js` `_emitSamples`. Keys go through `JsonOut::str`, so they are escaped.
- **Order.** The event comes before `load {phase:'preload'}` and before the preload and prepare replies. It is
  registered on the same keys ahead of the reply waiter, and `finish()` runs waiters in order. In the ui-core devhost
  log, 67 prepares with a sampler and 148 preloads with a sampler all had an event naming every one of their samplers
  before the reply. There were 0 violations.
- **Unknown ids read `true`.** This is the rule `get sampleStatus` already used (no jobs means settled). It matches
  `controller.songReady`, which skips a sampler the registry does not know. A sampler the core knows reads `true`
  without being decoded only when every one of its samples failed or was refused at the hard cap, because `failed`
  counts as settled. That is the existing rule, and it is the same in both paths.
- **Superseded prepare.** The `whenSettled` callback fires when its keys settle and reports the truth at that time.
  Waiters live in `inflight_` until `finish`, so there is no leak.
- **No event on eviction, memory trim or rate change** (by design). A song that is not being prepared can keep a
  stale `true`. The switch path corrects itself: every prepare emits before its reply.
- **Rate change.** A decode in flight is dropped (not stored, not failed), so the event says `false`. The unit's own
  re-decode sends no event later, so a chip can read "loading" until the next preload or prepare. This was the same
  before F1 (open item 2).
- **Threads.** The emit runs on the control thread only: `pump`, the op handlers, or inline offline. TSan is clean.
- **No emission storm.** One ui-core run had 217 `samples` events for 198 preloads and 102 prepares. Each event named
  at most 5 ids, and they totalled 16 KB. `get sampleStatus` was sent 146 times (preloads still ask, by design).
- **`_failed` (informational, not fixed).** The event has no `failed` flag. `_markSamples(id, true, false)` drops the
  id from `_failed`, so a failed sampler shows as not failed after its event. Nothing changes as a result: the only
  readers, songReady and main.js, use `held || failed`.

**S2 (low; fixed): shim rounds could overlap.** `_sampleStatusRound` set `_ssAsking = new Set(list)` and assumed one
round in flight. With a transport that delivers queued messages inside `post()` (the sync loopback), an event arriving
during round A's `_req` re-entered `_refreshSampleStatus` before `_ssBusy` was set. That started round B at once, and
B's Set replaced A's. An event behind A's older reply was then not re-asked, and `_loaded` kept the stale value.

The new fuzz (`sample-status-fuzz.test.mjs`, seeded, 2 × 600 interleavings over FIFO batches, microtask and macrotask
yields, preload, prepare and direct refreshes) failed in both modes on the builder's version, first at seeds 174 and
100258. Fix: `_ssAsking` is now a per-id count of the rounds in flight. All 1200 seeds pass. A control run with the
re-ask disabled diverges, which shows the fuzz can fail. The core's own transports (WKWebView, WebSocket) never
deliver inside `post()`, so production was not affected.

**S1 (medium; fixed): the xrun allowance hid real render blocks.**
- **What I measured.** I added env-gated mutations, then reverted them and checked the md5s. A 4 ms block in
  `TestInstrument::noteOn` gave 8 xruns. It passed the builder's `xruns ≤ min(3 + late, 50)` whenever the box showed
  5 or more late wakeups: the allowance was 9 under two `yes` loops and 46 under four. A 4 ms stall every 32nd quantum
  (35 xruns) also passed under four `yes` loops (allowance 36-44).
- **Fix: the cap is now 20.** Clean runs showed 0-2 noise xruns, even at 56 late wakeups, and CI's worst reading is 6.
- **Fix: a new per-note-on check.** The host thread reads `rig_get_meters` after each render. When `voices` rises,
  that call and the next two make the note's window. At most 4 of the 8 note-ons may have an xrun in their window,
  however loaded the box is, and the test also checks that at least 6 note-ons were seen.
- **Results.** Clean runs: 0-1 note-on windows with an xrun (idle 5×, two `yes` loops 10×, four `yes` loops 6×). The
  per-note mutation: 8/8, failing in every load setting. The every-32nd-quantum and every-quantum mutations fail the
  total check.

**Timing bounds (verified, judged defensible).** The mutations were run here, idle and under two `yes` loops:
- A 300 ms sleep in `opPrepare` fails 5 cases idle (bound 100) and 6 loaded (bound 140-146), including the O-AW-4
  case.
- A 300 ms sleep in `cache preload` fails 5 cases both idle and loaded.
- Unmutated: 7/7 idle (idle gap 35-37 ms) and loaded (idle gap 45-61 ms, bound 135-183, real gaps 46-51 ms).

k = 3 with the 250 ms cap is defensible. The defect this file guards is a loop held for a whole decode or build
(300 ms to several seconds), and every box fails that. A hold shorter than the bound (for example 150 ms on a noisy
runner) is not caught, and no tick-gap bound on shared CI could catch it. The sanitized cap of 1000 ms means sanitized
builds catch only multi-second holds, which is acceptable because Release carries the bound.

**S3 (medium, Swift; fixed, pending CI).**
- **The problem.** `offerFirstLaunchImport` dated the newest *Electron* library, but Yes staged `latestAnywhere()`,
  which also reads the app's own rotation. If an own backup was newer (site data reset, library pristine again), Yes
  imported a file the dialog never named, and the answer was stored, so the offer was never shown again.
- **The fix.** `stageOfferedAndImport(e)` stages `payload(e)`. If that file no longer parses, the result is
  "stage-failed", never a substitute.
- **Stand-in and test.** `lib.mjs` was changed to match, and a new migration-1x test fails on the old stand-in.

**S4 (low, Swift; fixed, pending CI).** `payload` now returns nil when the `.fileSizeKey` size is over `maxBytes`,
before it reads the file. Before, a 100 MB stray file was read whole and then dropped. The parse was already skipped
for such a file.

**Swift by reading (no defect).**
- **Booleans.** `CFGetTypeID(n) != CFBooleanGetTypeID()` rejects JSON booleans, which arrive as `__NSCFBoolean`, on
  both macOS and iOS.
- **`is` on `Any?`.** `songs is [String: Any]` looks through the optional, and nil reads false.
- **Schema.** `schema` null, string or bool is refused, exactly as `store.migrate` throws.
- **mtime ties.** `git archive` gives both fixtures the commit mtime, so the later name (the truncated file) is
  tried first. That means the self-test really exercises the skip.
- **iOS.** `electronEntries()` returns `[]`, so the offer reports "no-backup".
- **Self-test.** The migration step stages the 20261101 file and its marker. I expect it to pass.
- **Known divergence (not fixed).** `JSONSerialization` accepts a UTF-8 BOM and `JSON.parse` does not, so a BOM'd
  library passes `isLibrary` and is then refused by the store (open item 3).

## Open items

1. **Stale states after events that are not reported.** Eviction, critical memory trim and a rate change leave a
   setlist chip "ready" (eviction, trim) or "loading" (rate change). This needs an owner's call: either an event on
   these transitions or a shim re-ask on `state` sampleRate change.
2. **`unit.core3` flake.** The 16-organ tick gap read over 50 ms once under clang `-j2`. It is pre-existing and has
   no F1 code path.
3. **BOM'd backups.** A backup that starts with a UTF-8 BOM is treated as a library by Swift but refused by the store.
   It is very rare, and Electron never writes one.
4. **Untested iOS compile.** `apple-sim` is environment-only on CI, so the iOS compile of the shared Swift file is not
   proven by any job.

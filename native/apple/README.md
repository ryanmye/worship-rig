# Worship Rig native shell (Apple) -- UNBUILT

Status: every Swift, C and YAML file here is UNBUILT and UNTESTED. It was written on Linux, with no Xcode, no
compiler for Apple frameworks and no device. Expect compile errors on first build. Architecture, bridge and the
follow-up decisions (recording, migration, memory, audio session) are in `../docs/SHELL.md`.

## Layout

- `project.yml`: XcodeGen spec. Targets `WorshipRig-macOS` (macOS 14.5) and `WorshipRig-iPad` (iPadOS 17.5).
  `app/` and `docs/` are bundled as folder-reference resources. `RigCore.xcframework` comes from
  `scripts/build-core.sh`.
- `scripts/build-core.sh`: CMake build of `native/core` (target `rig_core`) for macOS arm64, iOS arm64 and an
  optional simulator slice, merged into `build/RigCore.xcframework`. Flags: `--mac-only`, `--sim`.
- `Sources/Shared/`: `WorshipRigApp` (SwiftUI, menu commands, onOpenURL), `RigHost` (engine, web view, event pump),
  `RigNavigation` (nav delegate, crash recovery, external links), `RigLibrary` (window.rig polyfill, backups, Electron
  import), `RigLifecycle` (memory pressure), `RigAudio` (device and AVAudioSession lifecycle), `RigMIDI`,
  `RigSchemeHandler` (`rig://app/`), `RigPaths`, `RigWebView`, bridging header.
- `Sources/Audio/`: C. AUHAL (macOS) and RemoteIO (iPad) render callbacks, device list, file decode, CoreMIDI UMP to
  bytes.
- `Sources/macOS`, `Sources/iPad`: empty, reserved. `Config/`: plists and entitlements are generated by XcodeGen.

## First-build checklist (for a Claude Code session on the Mac, follow in order, stop at the first failure)

0. Preconditions: Apple silicon Mac, macOS 14.5+, Xcode 15.4+ (`xcodebuild -version`), command line tools selected
   (`xcode-select -p`), `xcodebuild -runFirstLaunch` done once, repo on branch `v2-native`.
1. Tools: `brew install xcodegen cmake ninja`. Check `xcodegen --version`, `cmake --version` (3.24+).
2. Core sanity on the Mac first (Apple clang, arm64): `cmake -S native/core -B /tmp/rig-core -G Ninja
   -DCMAKE_BUILD_TYPE=Release && cmake --build /tmp/rig-core && ctest --test-dir /tmp/rig-core`. If this fails it is a
   core problem (report it, do not patch Swift).
3. Static libs and xcframework: `cd native/apple && ./scripts/build-core.sh --mac-only`. Expect
   `build/RigCore.xcframework` with one macOS slice and `Headers/rig/rig_engine.h`. `lipo -info
   build/lib-macos/librig_core_all.a` must say arm64. (Why a static lib: CMake stays the one source list of the core and
   Xcode only links.)
4. Project: `xcodegen` (writes `WorshipRig.xcodeproj` and `Config/Info-*.plist`), `open WorshipRig.xcodeproj`.
5. macOS build from the shell, no UI: `xcodebuild -project WorshipRig.xcodeproj -scheme WorshipRig-macOS
   -configuration Debug -destination 'platform=macOS' build 2>&1 | xcbeautify` (or `| tail -80`). Fix compile errors
   (section below), re-run until green. Ad-hoc signing (`CODE_SIGN_IDENTITY: "-"`) needs no account.
6. Run: Product > Run (or `open` the built app). Check in order: window opens; page loads from `rig://app/`; log shows
   `hello`; the six themes render; library survives relaunch; `audio start`, press a key, sound.
7. iPad build for a real device (needs the iOS slice): `./scripts/build-core.sh` (without `--mac-only`; add `--sim`
   for the
   simulator). Then `xcodegen` again.
8. Free Apple ID signing: Xcode > Settings > Accounts > `+` > Apple ID (creates a "Personal Team"). Select target
   `WorshipRig-iPad` > Signing & Capabilities > Team = your Personal Team (or put the team id in `DEVELOPMENT_TEAM` in
   `project.yml` and rerun `xcodegen`). If "Failed to register bundle identifier", change `bundleIdPrefix` and
   `PRODUCT_BUNDLE_IDENTIFIER` to something unique (e.g. `com.<yourname>.worshiprig`).
9. iPad: connect by cable, unlock, tap Trust. Settings > Privacy & Security > Developer Mode > on, the iPad restarts,
   confirm after restart. In Xcode pick the iPad as the destination and Run. First launch says "Untrusted Developer":
   Settings > General > VPN & Device Management > your Apple ID > Trust, then open the app.
10. Free-account limits: the install expires after 7 days (the app stops launching; rebuild and Run again, data in the
    app container is kept if the bundle id is unchanged), a few installed apps and about 10 new App IDs per week.
11. Then the Mac verification list below; write results into `native/docs/SHELL.md`.

## Expected errors (most likely first)

- `'rig/rig_engine.h' file not found` in the bridging header: the xcframework headers are not on the path. Both
  targets set
  `HEADER_SEARCH_PATHS = Sources/Audio ../core/include`; check `xcodegen` kept it. A static-library xcframework has no
  module map, so the bridging header is the only way in: keep it.
- `Undefined symbols ... _rig_*` or `std::` symbols at link: `build-core.sh` merged the wrong `.a` files, or `-lc++`
  missing (`OTHER_LDFLAGS`). `nm -g build/lib-macos/librig_core_all.a | grep rig_host_memory_pressure` must show `T`.
  A core older than T00b lacks `rig_host_memory_pressure`/`rig_set_paths`: rebuild the core.
- iOS slice: CMake `try_compile` fails with a signing error: add `-DCMAKE_TRY_COMPILE_TARGET_TYPE=STATIC_LIBRARY` to the
  `ios` and `iossim` `build_slice` calls. `-Werror` hits in the core under Apple clang: report to the core owner.
- `xcodebuild -create-xcframework`: "equivalent library definitions" when two slices share a platform; the macOS, iOS
  and simulator slices must differ by platform. Remove stale `build/` first.
- Swift: `value of type 'RigHost' has no member ...` or "self used before super.init" in `RigHost.init`: all stored
  lets (`scheme`, `bridge`, `navigation`, `library`, `webView`) are assigned from locals before `super.init()`.
- Swift: `WKScriptMessageHandlerWithReply` closure/Sendable warnings (Swift 5.9 shows them as warnings; if the build
  uses strict concurrency they are errors: set `SWIFT_STRICT_CONCURRENCY = minimal`). `callAsyncJavaScript` result
  typing (`Result<Any, Error>`) may need `(v as? Bool)`/`as? NSNumber`.
- Swift: `UIWindowScene.keyWindow` needs iOS 15+ (fine at 17.5); `NSAlert`/`NSOpenPanel` only under `#if os(macOS)`;
  `UTType.json` needs `import UniformTypeIdentifiers` (present in RigLibrary).
- Swift: C struct field names (`rig_config.recordings_dir`, `event_user`, `rig_host.audio_start` signatures, enum
  `RIG_DEVICE_INTERRUPTED`) must match `rig_engine.h` exactly; the Swift was written from the header text, not imported.
- C: `rig_apple_audio.c` on iOS: CoreAudio-only symbols (`AudioDeviceID`, `kAudioHardware*`) must be inside
  `TARGET_OS_OSX`; `kAudioUnitSubType_RemoteIO` vs `HALOutput` selection; `AudioConvertHostTimeToNanos` was replaced by
  `rig_apple_host_to_ns` (SETUP_REVIEW S3).
- XcodeGen: "folder `../../app` is outside the project" warning is expected (folder reference). Duplicate
  `Info.plist` ("Multiple commands produce") means `GENERATE_INFOPLIST_FILE` and `info.path` both active.
- Runtime, blank window: the scheme handler did not answer. Safari > Develop > <machine> > Worship Rig (Debug builds are
  inspectable) and read the console. CSP `'self'` may not match `rig:`: name the scheme in the CSP in
  `app/index.html` (an app edit, report it).
- Runtime, `main.js` import error: the on-the-fly patch needle moved; apply the one-line edit of SHELL.md section 2.
- Runtime, AUHAL/RemoteIO opens but silent: check `rig_host_audio_started` was called (log) and the rate matches.
